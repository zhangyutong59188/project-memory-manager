# 使用说明

使用 `$project-memory-manager` 可显式调用此 skill；当工作跨越多个会话并需要保存项目上下文时，也可以由 Codex 自动选择。

## 初始化项目

在项目根目录将 `assets/memory-template/` 中的模板复制到 `.memory/`，再用已核实的信息替换空白项。路径尽量使用相对路径，日期使用 `YYYY-MM-DD` 格式。

## 工作过程中更新

只添加会影响未来开发的长期信息。每条技术决策或问题记录使用一个带日期的标题。当里程碑或下一步发生变化时，更新 `PROJECT_STATE.md` 和 `TODO.md`。环境信息和资源路径必须先在当前工作区核实。

这个 memory 系统应当像项目开发笔记，而不是普通日志，重点记录为什么这样做、哪些方案被否定、哪些错误不要再次发生，以及重要路径在哪里。

## 后续扩展

可以增加实验记录、数据版本、实验报告或 Git 提交关联等章节或文件。如果新文件成为标准工作流的一部分，请同步更新 `SKILL.md` 中的文件约定。

## 管理多个子项目

在总项目根目录的 `.memory/SUBPROJECTS.md` 登记每个子项目的名称、路径、用途、状态和依赖关系。每个真正的子项目可以在自身目录下拥有独立的 `.memory/`，其中保存自己的 `PROJECT_STATE.md`、`ENVIRONMENT.md`、`ASSETS.md`、`DECISIONS.md`、`FAILURES.md`、`SESSION_LOG.md` 和 `TODO.md`。

开始任务时先确定当前所在的子项目，再读取该子项目的 memory；不要把兄弟子项目的状态混入当前任务。跨子项目任务分别更新各自的 memory，并只在根目录记录共享决策、依赖关系和整体进度。
